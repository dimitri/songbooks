Guitar Pro import

Bring in the whole band.
Not just the chords.

A Guitar Pro file already has the drum pattern, the bass line, and every guitar part written out — the import wizard reads all of it, maps it onto your song's own sections, and keeps each part as real, playable notation instead of flattening everything into one chord grid.

{{template "icon-mode-drummer"}} Drums, for real

Every hit comes in as real GM percussion notation — kick, snare, hi-hat, toms, cymbals — not a generic "drums" placeholder. Shows up in Drummer view, the whole song as one continuous staff.

{{template "icon-mode-jazz"}} Bass, with its own tuning

The bass track keeps its exact tuning and fingering from the file — nothing re-derived or guessed. Viewable as real tab notation right alongside the chord chart.

{{template "icon-mode-normal"}} Any number of guitars

Rhythm, lead, a second rhythm part — each guitar track comes in as its own voice, independently viewable, never merged into one.

How it works

A short, guided wizard — not a silent all-or-nothing upload. You bring in one track at a time, each time confirming it lines up with the song before anything saves.

Pick a file and a track

Drop in a .gp, .gp3, .gp4, .gp5 or .gpx file — read entirely in your browser, nothing uploaded until you commit. Choose which one of the file's own tracks to bring in first (drums, bass, a specific guitar — you run this step again for each additional part you want).

Line it up against the song

Guitar Pro files routinely carry a count-in or a silent intro bar the chart doesn't have — so this step is a waveform timeline (using the file's own embedded backing track and its real per-bar sync points, not a guess), where you drag section boundaries to match where your song's own sections actually start.

Preview, then commit

See exactly which bars will land in which section before anything is saved — including the file's own embedded backing-track audio, if you want it imported alongside the notation, synced to the same bars.

One track per run, by design. A GP file's drum, bass and guitar parts each get their own alignment and their own review before saving — a shared alignment step for every part at once would hide a mismatch in whichever track you weren't looking at. Running the wizard once per part you want takes a minute longer and never silently misaligns one of them.

Section mapping

The import never invents a song structure of its own — it maps the file's bars onto the sections your song already has (or that you set up first), bar for bar.

WhatHow
Section boundariesShared, draggable handles on the alignment timeline — the end of one section is always the start of the next, so there's no way to leave a gap or an overlap between them.
Bar timingRead from the file's own per-bar sync points (real, human-authored-and-synced data), not guessed from the audio — confirmed far more reliable than beat-detection for this.
Count-in / silent barsHandled by the alignment step itself: drag the first boundary to wherever your song's own bar 1 actually starts in the file.
Backing-track audioOptional, imported with the same bar sync the notation uses, so playback and the chart stay lined up.

Where each part shows up

No separate "Bass view" or "Guitar view" to hunt for — every imported part lives inside the same chart you already read.

PartWhere to see it
DrumsDrummer — a dedicated view, the whole song as one continuous drum staff with chord names floating above it, same as a real drummer's chart.
Bass / GuitarSong or Song map, via the instrument picker next to the view tabs — pick which track's full notation overlays the chart. Pick "Chords" to go back to the plain chord grid.

A section with more than one melodic track (bass AND a guitar, say) keeps its shared chart as pure chords by default — the instrument picker is what decides which one's detailed notation you're looking at, so nothing gets silently guessed or merged.

It's still your song file

An imported track isn't a separate attachment living outside the song — it's written straight into the same plain-text .song file as everything else, the same score[label]: field a hand-written riff uses.

Edit it like anything else

Open Source and the imported notation is right there, in the same file as the chords and lyrics — nothing locked behind a special importer-only format.
